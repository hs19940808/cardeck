# 昂克赛拉按键与旋钮

适用本次无触摸屏的昂克赛拉 + smartBox 连接。输入依据为导出日志中的 HID 描述符；
下表描述代码已接入的行为，实车验收尚待完成。

| 输入 | 已接入行为 |
| --- | --- |
| 旋转 | 相对正增量向后选焦点，负增量向前选；连续同值报告不丢刻度 |
| 四向拨动 | 上下左右方向键，按住后重复，松开停止 |
| 旋钮确认 | 完整 DOWN/UP；保留长按时刻和重复事件 |
| 返回 | 向当前虚拟屏发送 Android 返回；Dock 中返回此前应用的焦点，桌面根页面保持常驻 |
| 主页 | 复用桌面/仪表盘循环；普通 requestUI 唤起桌面 |
| 导航快捷键 | requestUI maps: 打开已设置的默认地图，缺少地图时回桌面 |
| 音乐快捷键 | requestUI music: 打开已有媒体仪表盘 |
| 播放、上一曲、下一曲、播放/暂停 | 按各设备描述符解释 Array 或位图，按下沿触发，避免状态轮询造成连点 |

自有桌面、Dock 和设置显示青色焦点边框；旋转可跨桌面分页并接续 Dock。
跨屏后隐藏离开屏幕的焦点描边，保留其原焦点；弹窗获得焦点时隐藏底层窗口的描边。
设置中的滑条用左右拨动调整，分辨率在每次用户调节时保存，不依赖触摸松手。
标准事件通道、蓝牙保活通道与 Wi-Fi iAP2 隧道均已接入输入队列。iAP2 两条通道
共用 `Iap2HidSession`，按组件编号保存描述符；停止组件或通道退出时补发取消式松开，
不同通道的同键状态在注入前统一合并。第三方应用接收虚拟屏键盘事件，
其自身不支持键盘焦点的控件无法仅凭协议解析保证可操作。

语音请求、通话桥接尚未实现。收藏等未在当前实车描述符和日志中确认的按钮不作猜测映射；
车机原生处理的按键也不一定会转发到手机。

## 2026-10-22 切屏修复

08:21 导出的实车日志中，导航键已发出 `requestUI maps:`，手机虚拟屏也已打开地图，
视频持续发送至第 1417 帧。此前的“页面唤起=true”只表示手机端页面切换，不能证明
原车屏幕已经显示 CarPlay。

代码中的 `modesChanged` 资源通知误走 RTSP 控制连接；这次改为与 HID 控制命令相同的
事件连接，使用该连接的 Events 密钥和独立 CSeq。控制连接的 `200 OK` 不再作为资源
通知成功的证据。另补上 `/info.modes` 初始资源请求，避免原车仍占屏时就声明手机占屏。

新增本地模拟车机回放，覆盖明文/加密通知、原车接管、释放后导航唤起、应答 CSeq 及
断开后的发送拒绝。实际马自达屏幕能否切入仍需安装本次测试包后确认。

新日志依次检查：

- `AIRPLAY: 初始资源请求`：车机在 `/info` 中给出的初始状态及处理结果。
- `AIRPLAY: modesChanged(事件通道) 已发送=true`：通知已写入事件连接。
- `EVENT: modesChanged 应答 CSeq=...`：车机对对应通知的实际回复。
- `手机虚拟屏页面切换=true`：手机端目标页面已切换，仍须与车机显示结果对照。

媒体订阅也已接入现有缓存，支持标题、歌手、专辑、时长、进度和播放状态，按订阅
筛选并最多每秒发送变化；停止订阅或断链后停止推送。播放进度使用播放器的更新时间
外推，避免每秒重新采样时回跳。封面文件传输、语音和通话桥接仍未实现。

## 软件检查

- 原始 67B 旋钮描述符：确认/返回位、X/Y 正负值、相对旋转及短包拒绝。
- Report ID、位偏移、填充、绝对旋转位置、Hat Switch 与非控制器设备隔离。
- smartBox 媒体位图中的主页和音频键分流，奥迪 Array 和本田位图回归。
- 连续按住只产生一次按下，释放原键后再按新键，不同报告 ID 不相互释放。
- 多个来源按住相同键时只发一次 DOWN，最后一个来源松开后才发 UP。
- 组合描述符按 Application 分流旋钮和媒体字段；iAP2 媒体状态按 Report ID 合并。
- 空 data、多参数缺 data 和无描述符的多字节报告不能误触发媒体键或释放现有按键。
- 真实分页编号、首尾接续和连续快速跨页；iAP2 封装后的旋钮/主页报告。
- iAP2 多组件隔离、组件编号 65535、重注册、StopHID 和通道关闭后的迟到帧。
- StopHID、重注册和断链保留取消标记，避免把确认键的异常结束当作一次点击。
- 标准描述符参数 4 与旧参数 2 的兼容；长扩展字段不能抢占描述符。
- 模拟车机完整蓝牙握手后，在保活泵里交替发送两种组件，验证连续相同 Wheel +1
  均被消费、StartHID 应答回显真实组件编号、StopHID 产生松开。

输入仅在当前会话虚拟屏就绪后启用；推流结束时同时关闭入口、使旧队列失效并取消长按。
连接准备中和结束后到达的 HID 报告不再驱动遗留虚拟屏。

## 实车验收

安装前结束会话并 force-stop CarDeck，再覆盖安装；Shizuku 应处于已授权状态。
本地测试包沿用 debug 证书，能覆盖相同证书的旧测试包，不能覆盖正式证书签名的安装。

1. 连接后按导航键，确认能进入 CarDeck 的默认地图。
2. 回到桌面，正反各旋转多格，确认焦点可见、每格一次，能够跨页并进入 Dock。
3. 四向拨动并按下确认，确认能选择应用、打开设置和操作设置控件。
   在显示设置中调节分辨率后退出再进入，确认值已保存；从 Dock 按返回，确认焦点
   回到此前的应用控件。冷启动时快速切换设置面板，也应能正常返回并继续操作。
4. 按住方向/确认后松开，确认重复停止，切换页面及断开后没有残留按下。
5. 在应用和设置内使用返回，使用主页及导航/音乐快捷键返回对应页面。
6. 播放音乐，测试上一曲/下一曲/播放，确认单次按键没有重复执行。
7. 对默认地图等第三方应用分别检查焦点、确认和返回；旋转正负值对应的实际
   顺/逆时针方向也在这一轮确认。

问题定位查看本次启动日志中的 `EVENT: 控制器`、`EVENT: requestUI`、`IAP-HID:` 和 `KEY:`。
报告解析成功、按键注入成功与车机实际显示/响应是三个不同的验收层次。

## 协议与焦点参考

- [USB HID Usage Tables 1.7](https://usb.org/sites/default/files/hut1_7.pdf)：Usage Page、轴、Wheel 和 Consumer 按键的含义。
- [Android 键盘导航](https://developer.android.com/develop/ui/views/touch-and-input/keyboard-input/navigation)：可聚焦控件、Tab 顺序与方向键导航。
- [Android 按键取消语义](https://developer.android.com/reference/android/view/KeyEvent#FLAG_CANCELED)：异常结束使用带取消标记的 UP；第三方控件仍须正确处理该标记。
- [公开的 iAP2 使用示例](https://patents.google.com/patent/WO2017177302A1/en)：StartHID 的组件编号参数 0、描述符参数 4，以及报告数据参数 1。
- [Apple 配件接口规范 R2 的公开镜像](https://www.scribd.com/document/325596037/MFi-Accessory-Interface-Specification-for-Apple-Devices-R2)：26.8 节的 HID 组件、报告与 StopHID 生命周期。
- [CatPlay 的事件客户端实现](https://github.com/catplay-labs/catplay/blob/master/carplay/catplay_carplay/src/events/events_client.rs)：事件连接上的 `/command` 传输和 Events 密钥。
- [Apple 资源管理说明](https://developer.apple.com/videos/play/wwdc2016/723/)：原车发送资源请求，手机发送资源状态通知。
